# Foundation Definition of Done

The TOS foundation is complete when:

1. The official name is consistently TopShelf Operating System and all deprecated aliases are identified.
2. Every foundational architecture and authority term has a controlled definition and conflicting aliases are prohibited or mapped.
3. All 105 catalog contracts have agnostic templates using the common envelope.
4. Every project must evaluate every contract as required, conditional, or not applicable with reason.
5. Core record schemas validate project manifests, facts, tasks, evidence, modules, decisions, promotions, and agent work orders.
6. The canonical state model, lifecycle states, truth states, evidence classes, task states, priorities, severities, and decision states are controlled enums.
7. Owner authority, reserved actions, agent separation, capability grants, credential/authority separation, and human override are explicit.
8. The TOS control-plane/kernel boundary is canonical: userland may observe/reason/propose, while TOS-managed privileged mutation requires the deterministic execution-kernel admission path once implemented and proven.
9. Current implementation truth is explicit: foundation-kernel capabilities may exist while autonomous privileged execution remains blocked until execution-kernel mediation has code, negative tests, exact-candidate evidence, and promotion approval.
10. Architecture and contracts forbid privileged bypass, self-granted capability expansion, evidence greenwashing, and silent TSAL/workload adoption.
11. The build roadmap, Teach strategy, promotion rules, recovery rules, module model, adapter model, TSAL/TOS/workload boundary, and upgrade model are approved.
12. The package manifest contains checksums for all published files or is explicitly classified as a historical manifest under a newer authoritative mechanism.
13. The master DOCX and PDF pass visual QA without clipping, overlap, broken tables, missing glyphs, or blank defect pages when those distribution artifacts are produced.

The foundation does **not** claim autonomous privileged operation merely because the architecture is documented. Autonomous privileged roles remain disabled until the execution kernel satisfies its implementation and evidence gates.
